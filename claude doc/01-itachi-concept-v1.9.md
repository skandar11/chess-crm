# Itachi — AI-автоматизация для малого бизнеса

_Концепция студии | Версия 1.9 | 11.03.2026_

---

## Что мы делаем

Берём малый бизнес с ручными процессами — таблицами, мессенджерами, бумажными журналами — и переводим их на AI-автоматизацию. Под ключ.

Менеджер продолжает писать в Telegram как привык. Система понимает его, записывает данные, отвечает на вопросы и сама напоминает о важном.

---

## Почему это работает

Большинство автоматизаций проваливаются не потому что технология плохая, а потому что люди не меняют привычки. Мы не просим менять привычки — мы встраиваемся в то что уже есть.

Telegram уже открыт весь день. Писать туда — нулевой барьер входа. Не нужно учить новый интерфейс, заходить в CRM, вспоминать пароль.

---

## Чем отличаемся

| Альтернатива | Проблема |
|---|---|
| Готовые CRM (Bitrix, AmoCRM) | Слишком сложно, не под их бизнес, нужно обучение |
| Zapier / Make / n8n | Требует технического человека внутри, нет AI-интерфейса |
| Разработка под заказ | Дорого, долго, потом некому поддерживать |
| Excel / Google Sheets | Данные расползаются, нет аналитики, нет автоматизации |

Мы делаем то что другие не делают вместе: **русскоязычный AI-интерфейс + локальное хранение данных + настройка под бизнес-логику конкретного клиента**.

---

## Архитектура

```
Менеджер -> Telegram -> Claude API (намерение + нормализация) -> C# бэкенд -> PostgreSQL
                                                                       |
                                                                Google Sheets (зеркало, append-only)
                                                                       |
                                                                Metabase (просмотр и аналитика)
```

## Инструменты просмотра данных

Варианты интерфейса для просмотра данных — от простого к сложному:

- **Metabase** — подключается к PostgreSQL напрямую, показывает таблицы и дашборды без кода.
  Деплоится через Docker. Источник правды — PostgreSQL, Metabase только читает.
- **Google Sheets** — зеркало для менеджера. Бот пишет туда при каждой операции (append-only).
  После ручных правок может расходиться с БД — это нормально, источник правды всегда PostgreSQL.
- **Blazor / React** — веб-интерфейс с редактированием. Рассматривается после закрытия пилота,
  только если Telegram-интерфейса не хватает.

Решение для пилота: Metabase (просмотр) + Google Sheets (зеркало) + Telegram-бот (ввод данных).

---

**Реализованный стек:**
- Классификация намерения — Claude Haiku (облако)
- Нормализация имён к именительному падежу — в том же промпте намерения
- SQL-генерация аналитики — Claude Haiku (облако)
- Форматирование ответа — Claude Haiku (облако)
- Доступ к БД — raw Npgsql (без ORM)
- Google Sheets API — зеркало данных для менеджера (одна таблица: CRM)

**Два независимых приложения:**
- **ChessCrm.Bot** — Telegram-бот (основной продукт)
- **Скрипт миграции** — одноразовый импорт данных (отдельный проект, отдельный разработчик)

**Эволюция стека — план:**
- Итерация 4-5: гибридный режим — сначала локальная модель (Ollama), при ошибке — fallback на Claude API
- Итерация 6+: накопление пар вопрос->SQL через `query_feedback`, дообучение локальной модели

## Модель работы

**Внедрение** — низкая стоимость. Продаётся через "окупается за первый месяц".

**Подписка** — поддержка, изменения, развитие. Основной доход студии.

Мы не продаём технологию. Мы продаём **отсутствие головной боли**.

### Уровни подписки

| Уровень | Что внутри |
|---------|-----------|
| Базовый | Claude API + few-shot обучение на данных клиента |
| Продвинутый | Ollama на сервере клиента + Claude API как fallback |
| Премиум | Fine-tuned модель на данных клиента — AI который знает именно этот бизнес |

## Целевые вертикали

Подходит везде где есть: регулярные клиенты, ручной учёт, повторяющиеся операции и один-два менеджера.

1. Учебные центры, спортивные секции, детские школы
2. Салоны красоты, сервисы по записи
3. Небольшая логистика, доставка, склад
4. Любой малый бизнес с бумажной или Excel-работой

**Фокус:** малые города и рынки типа Казахстана — там меньше конкурентов, выше лояльность, острее боль от ручных процессов.

**Первый живой кейс:** шахматная школа (март 2026) — Telegram-бот с AI-аналитикой, 3 командами записи (ученик, группа, абонемент) и зеркалированием в Google Sheets CRM, работающий через Claude API.

## Настоящий моат

Технологию можно скопировать. Труднее скопировать:

- **Бизнес-анализ** — понять как работает конкретный бизнес с его тетрадками и привычками. Это человеческая работа, её нельзя автоматизировать.
- **Накопленную экспертизу по вертикалям** — каждый внедрённый проект становится шаблоном для следующего в той же нише.
- **Базу лояльных клиентов** — малый бизнес не меняет подрядчика если тот решает проблему.
- **Данные для дообучения** — накопленные пары вопрос->SQL по конкретному бизнесу. Это нельзя купить.

## Принцип: итерации, а не идеал с первого раза

Автоматизация внедряется последовательно — спринтами по 1-2 недели по принципу agile.

**Приоритет итераций определяется двумя критериями:**
1. Какие процессы самые частые — то что менеджер делает каждый день
2. Какие процессы больше всего влияют на финансовые показатели — оплаты, абонементы, долги

Начинаем с самых простых и частых операций. Усложняем только после того как простые работают стабильно.

**Про провальные итерации:**
С AI-автоматизацией нормально сделать несколько попыток, выкинуть код и переделать заново. Это не провал — это процесс. Стоимость итерации с AI значительно ниже чем в классической разработке, поэтому можно позволить себе пробовать, ошибаться и находить правильную структуру экспериментально. Главное — не тащить плохое решение дальше из-за нежелания переделывать.

Каждая выброшенная итерация — это накопленное понимание бизнес-логики клиента, которое остаётся даже когда код меняется.

## Принцип: AI где нужно, код где достаточно

| Задача | Инструмент |
|--------|-----------|
| Записать данные в БД | Скрипт |
| Роутинг по условиям | Скрипт |
| Парсинг намерения из текста | AI (Claude API) |
| Нормализация имён (падежи) | AI (тот же промпт намерения, без доп. вызова) |
| SQL-генерация | AI (Claude API -> в будущем Ollama с fallback) |
| Форматирование ответа | AI (Claude API -> в будущем Ollama с fallback) |
| Fine-tuning | Локально, на накопленных данных |

Не нужно тащить AI туда где справляется простой код. Это снижает стоимость и повышает надёжность.

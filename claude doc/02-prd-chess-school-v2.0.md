# PRD — Шахматная школа #1
_Версия 2.2 | 11.03.2026 | alpha v5_

---

## Зачем этот проект студии

Шахматная школа #1 — пилот. Не просто первый клиент, а живая лаборатория где отрабатывается всё: архитектура, процесс внедрения, работа с менеджером, деплой, поддержка.

Всё что здесь сломается и починится — станет экспертизой. Всё что здесь заработает — станет шаблоном для следующих клиентов в той же вертикали.

Особый контекст: владелец школы и владелец студии — один человек.

---

## Проблема

Менеджер ведёт всё вручную в Google Sheets: список учеников, оплаты. Данные в нескольких таблицах, связи не контролируются.

Результат:
- Время тратится на рутину вместо работы с учениками
- Владелец не видит актуальную картину: долги, загрузка групп, доход
- Ошибки при вводе ничем не контролируются
- Любой аналитический вопрос требует ручной работы с таблицей
- Родители не имеют самостоятельного доступа

## Аудитория

| Роль | Кто | Что хочет |
|------|-----|-----------|
| Менеджер / Админ | Основной пользователь, не технический | Быстро вносить данные, получать ответы на вопросы |
| Владелец | Аналитика и контроль | Видеть долги, загрузку, доход — одним запросом |
| Родитель | Самообслуживание | Расписание ребёнка, статус абонемента |

Интерфейс — только Telegram. Никаких веб-панелей, форм, логинов.

## Роли в боте

## Архитектура

### Два независимых приложения

| Приложение | Назначение | Стек |
|-----------|-----------|------|
| **ChessCrm.Bot** | Telegram-бот с AI и записью данных | C# .NET 10, raw Npgsql, Claude API |
| **Скрипт миграции** | Одноразовый импорт из старых Sheets/CSV | Отдельный проект, отдельный разработчик |

### Как работает аналитика

```
Менеджер задаёт вопрос в Telegram
        |
Claude API / Haiku — классифицирует намерение
        |
Claude API / Haiku — генерирует SQL по схеме БД
        |
C# бэкенд — валидация (только SELECT, Guard ReadOnly)
        |
PostgreSQL — выполняет запрос
        |
Claude API / Haiku — форматирует ответ на русском
        |
Telegram — красивый отчёт менеджеру
```

Авто-исправление: если SQL вернул ошибку PostgreSQL — запрос идёт обратно в модель с текстом ошибки. Максимум 2 попытки.

### Как работает запись данных

```
Менеджер пишет в Telegram
        |
Claude API — определяет намерение + нормализует имена -> JSON
        |
TelegramBotService — резолвит группу из БД, строит превью
        |
Превью + кнопки OK / Отмена -> подтверждение
        |
Handler -> PostgreSQL + Google Sheets (зеркало)
        |
Подтверждение в Telegram
```

### Google Sheets — одна таблица CRM

| Переменная окружения       | Листы                              |
|----------------------------|------------------------------------|
| GOOGLE_SPREADSHEET_ID_CRM  | Ученики, Группы, Абонементы, Инвайты |

PostgreSQL — источник правды. Sheets — зеркало (append-only).
Metabase подключается к PostgreSQL и читает данные напрямую.

### Metabase

Open-source BI-инструмент для просмотра данных и аналитики. Запускается локально через Docker,
подключается к PostgreSQL напрямую.

Запуск: `cd ~/chess-automation/metabase && docker compose up -d`
Интерфейс: http://localhost:3000
Подключение к БД: host.docker.internal:5432, database chess_crm

Metabase не пишет в БД — только читает. Используется для:
- Просмотра таблиц клиентов, групп, абонементов
- Проверки данных после миграции
- Дашборда владельца (долги, загрузка групп, доход)

## Идентификация родителей

Родитель идентифицируется через персональную инвайт-ссылку:

1. Админ выполняет команду `/invite ФИО ребёнка`
2. Бот генерирует уникальный токен -> сохраняет в БД -> записывает в лист "Инвайты"
3. Админ копирует ссылку и отправляет родителю
4. Родитель переходит по ссылке `t.me/bot?start=TOKEN` -> бот привязывает `tg_id` к клиенту -> токен деактивируется

Ссылка одноразовая, действует 24 часа.

## Менеджерские команды

### US-A1: Оформить абонемент

Как Админ я хочу написать «Айгерим оплатила 15000 за апрель Никите» и чтобы бот нашёл клиента, показал превью и записал абонемент с получателем.

```
Админ: "Айгерим оплатила 15000 за апрель Никите"
        |
Claude API -> намерение: sell_subscription, клиент: Айгерим, сумма: 15000, период: апрель, получатель: Никита Квитко
        |
Поиск клиента (fuzzy + точное совпадение)
        |
Проверка дубля: абонемент за этот месяц уже есть?
        |
Превью -> OK / Отмена
        |
INSERT subscriptions (с recipient) -> Sheets «Абонементы» -> инкремент subscriptions_count
```

### US-A2: Новый ученик

Как Админ я хочу добавить нового ученика одной командой.

```
Админ: "Новый ученик Иванов Артём, 12 лет, мама Иванова Светлана, тел 7771234567, начинающий"
        |
Claude API -> намерение: new_student, JSON с полями (включая level, parent_name_2, parent_phone_2)
        |
Валидация на этапе превью:
  - Дубль имени (exact -> блок, fuzzy -> warning)
  - Дата рождения (будущая -> блок, < 3 лет -> warning)
  - Телефон: нормализация + проверка дубля (info)
  - Группа: существует, есть места
        |
Превью + предупреждения -> OK / Отмена / ✏️
        |
INSERT clients (с level, parent_name_2, parent_phone_2) -> Sheets «Ученики» -> AddToGroupHandler (если указана группа)
```

### US-A3: Записать в группу

```
Админ: "Записать Артёма Иванова в группу пн 16:00"
        |
Claude API -> намерение: add_to_group, group_name="пн16", group_1_day/time как fallback
        |
ResolveGroupLineAsync → DayOfWeekMapper (fuzzy prefix) → FindGroupAsync (каскад: name → id → day+time → day+hour)
        |
Превью -> OK / Отмена
        |
INSERT group_students (только БД, без Sheets)
```

### US-A4: Редактирование ученика

Как Админ я хочу изменить данные существующего ученика одной командой.

```
Админ: "Измени телефон Иванова на 7771112233"
        |
Claude API -> намерение: edit_student, клиент: Иванов, fields: {parent_phone: "7771112233"}
        |
Поиск клиента (fuzzy + точное совпадение)
        |
Чтение текущих значений из БД для превью
        |
Валидация (birth_date, phone, subscriptions_count >= 0)
        |
Превью (старое → новое) -> OK / Отмена
        |
UPDATE clients SET field=value WHERE id=clientId (только PostgreSQL, без Sheets)
```

Редактируемые поля: birth_date, parent_name, parent_phone, parent_name_2, parent_phone_2, level, notes, is_active, subscriptions_count.
Нередактируемые: id, full_name, created_at, parent_tg_id, parent_tg_username, invite_token, invite_expires_at, invite_activated_at.

### US-A7: Убрать из группы

```
Админ: "Убери Богдана из группы пн 16:00"
        |
Claude API -> намерение: remove_from_group, клиент + группа
        |
Поиск клиента + группы, проверка: ученик записан в эту группу?
        |
Превью -> OK / Отмена
        |
UPDATE group_students SET left_at = CURRENT_DATE (только БД, без Sheets)
```

### US-A8: Перенос в другую группу

```
Админ: "Перенеси Богдана из пн 16:00 в ср 18:00"
        |
Claude API -> намерение: transfer_group, клиент + исходная группа + целевая группа
        |
Поиск клиента, исходной и целевой группы
Если исходная не указана — автоопределение (1 группа = ОК, 0 = ошибка, 2+ = уточнение)
Проверка: есть места в целевой, ученик не в целевой
        |
Превью -> OK / Отмена
        |
UPDATE group_students (remove from source) + INSERT group_students (add to target) — только БД
```

### US-A5: Аналитика

```
Админ: "Кто не платил в этом месяце?"
        |
Claude API -> намерение: analytics
        |
SQL-генерация -> Guard ReadOnly -> PostgreSQL -> форматирование -> Telegram
```

### US-A6: Генерация инвайта

```
Админ: /invite Артём Иванов
        |
Поиск клиента -> генерация UUID-токена -> clients.invite_token
        |
Sheets «Инвайты» -> возврат ссылки t.me/bot?start=TOKEN
```

## База данных — chess_crm (v2.0)

```

user_roles      — роли (tg_id, role, client_id для родителя)
```

## Валидация и обработка ошибок

| Ситуация | Поведение | Тип |
|----------|-----------|-----|
| Ученик с таким ФИО уже есть (exact) | Блокирует превью, предлагает изменить ФИО через ✏️ | Блок |
| Похожее ФИО найдено (fuzzy, pg_trgm) | Warning в превью, можно нажать ✅ | Warning |
| Дата рождения в будущем | Блокирует превью | Блок |
| Возраст < 3 лет | Warning в превью | Warning |
| Телефон совпадает с другим учеником | Info в превью (не блокирует) | Info |
| Ученик не найден | "Не нашёл. Уточни имя." | Блок |
| Найдено несколько совпадений | Список + просьба уточнить ФИО | Блок |
| Группа не найдена | Ошибка до показа кнопок + подсказка формата | Блок |
| Ученик уже в группе | Предупреждение, не записывает повторно | Блок |
| Абонемент за этот месяц уже есть | Предупреждение, не записывает повторно | Блок |
| В группе нет мест (>=8) | Сообщение + показываем другие группы | Блок |
| Ученик не записан в группу | "Ученик не записан в эту группу" | Блок |
| В целевой группе нет мест (перенос) | "В группе [name] нет мест" — блокирует | Блок |
| Ученик уже в целевой группе | "Ученик уже в этой группе" | Блок |
| Ученик в нескольких группах (перенос без источника) | Список групп + просьба уточнить | Блок |
| SQL ошибка | Авто-retry с передачей ошибки в модель | — |
| Sheets недоступны | Запись в PostgreSQL сохраняется, предупреждение в Telegram | — |
| Инвайт-токен не найден / истёк | "Ссылка недействительна, обратитесь к администратору" | Блок |
| Пользователь без роли | "Нет доступа. Используйте персональную ссылку." | Блок |

Телефон нормализуется в формат `8 (XXX) XXX-XX-XX` при построении превью.

## Выученные уроки

| Проблема | Решение |
|----------|---------|
| Модель галлюцинирует год в датах | Передаём текущую дату в каждый промпт |
| Кириллица приходит как `\uXXXX` | `JavaScriptEncoder.UnsafeRelaxedJsonEscaping` |
| Модель оборачивает JSON в markdown фенсы | Стрипаем markdown-обёртку перед парсингом |
| `'valueInputOption' is required` в Sheets | Добавили `ValueInputOption = USERENTERED` |
| ILIKE находит "Даниил" при запросе "Данил" | Точное совпадение вытесняет fuzzy-кандидатов |
| "Попова Богдана" не матчится | Нормализация падежей в промпте намерения |
| Группа не проверялась до подтверждения | ResolveGroupLineAsync вызывается на этапе превью |
| Точный парсинг дня недели ломался на сокращениях | DayOfWeekMapper с fuzzy prefix matching (пон → monday, суб → saturday) |
| Минуты в расписании мешали поиску (16:00 vs 16:30) | 4-шаговый каскад FindGroupAsync: name → id → day+time → day+hour (fallback) |
| EF Core избыточен для бота | Переход на raw Npgsql — проще, быстрее, меньше зависимостей |
| Валидация после ОК поздно | Проверять дубли/ошибки на этапе превью — дешевле откатывать |
| pg_trgm может быть не установлен | Fuzzy-поиск с fallback: ловим PostgresException, возвращаем только exact |

## Риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Стоимость Claude API растёт | Средняя | Мониторинг расходов |
| Менеджер возвращается к Sheets | Средняя | Параллельная работа, простые первые команды |
| Нормализация падежей не для всех имён | Высокая | pg_trgm + доработка промпта |
| Родители не проходят онбординг | Средняя | Инвайты рассылает лично владелец |
